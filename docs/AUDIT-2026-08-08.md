Cross-repo engineering audit of the Mon toolchain, recorded per repo. The Hub repository that
publishes this package's artifact is audited separately, in

0.2.3 to 1.0.0 rewrite. Every finding is labelled with whether it exists in git or only on disk.

## High

### H1 — `encode()` is not injective; the documented round-trip invariant is false for two input classes

**Status:** uncommitted | **Location:** `src/mon_tokenizer/trainer.py:197-199` and `:186`; claim at
`src/mon_tokenizer/tokenizer.py:18-21`, `README.md:35`, `README.md:68`

**Evidence.** `Metaspace(replacement=WORD_MARKER, prepend_scheme="always")` maps both `" abc"` and
`"abc"` to the same pieces, and maps a literal U+2581 identically to a space:

```
encode(' abc')["ids"] == encode('abc')["ids"]     COLLISION
encode('a b')["ids"]  == encode('a▁b')["ids"]     COLLISION

decode(encode(' abc'))  -> 'abc'      # leading space gone
decode(encode('a▁b'))   -> 'a b'      # U+2581 corrupted
```

The claim being contradicted, `tokenizer.py:18-21`: *"any input reconstructs exactly … 100%
round-trip on Mon, Burmese, English and mixed-script text."*

**Reasoning.** The collision happens at encode, not decode, so no decoder can recover it.
`Strip(" ", 1, 0)` is correct only for input with no leading space.

**Impact.** Bounded but real. Trailing whitespace, interior runs, tabs, newlines, NUL and control
characters all round-trip correctly. U+2581 is a box-drawing character, plausible in exactly the
scanned-book and table content this tokenizer targets.

**Fix.** `prepend_scheme="never"` fixes it but changes every token id, which means a retrain. The
honest cheap alternative is to narrow the documented claim and add the two failing cases as `xfail`
tests, so the limit is recorded rather than denied.

### H2 — The documented release command cannot stage this release

**Status:** uncommitted | **Location:** `docs/how_to_contribute.md:55-58`

The documented sequence is `uv version --bump`, `git commit -am`, `git tag`, `git push --tags`.
`git commit -a` stages tracked modifications only. `git ls-files src/` returns five files; the
untracked set includes `normalization.py`, `syllable.py`, `metrics.py`, `trainer.py`, the 4.8 MB
`mon_tokenizer.json` artifact, `model_card.json`, and four of six test files.

Running it as written commits the version bump and the *deletion* of the old `.model` artifact while
omitting the replacement and four library modules. `__init__.py:19` imports `normalization`, so a
fresh clone of that commit cannot import the package at all.

**Fix.** `git add -A` before the bump. Trivial, and it is the first thing to do in this repo.

## Medium

### M1 — The round-trip measurement is structurally blind to H1

`scripts/export_corpus.py:106` calls `.strip()` on every line before export. A scan of the eval
corpus confirms the consequence: **0 lines with leading whitespace, 0 containing U+2581**. So
`roundtrip: 1.0` is true of a corpus that excludes the failure mode.

Three independent guards — the model card, `preflight.py:39`, and `test_tokenizer.py:61` — all probe
interior whitespace only, and therefore share one blind spot.

This is the same defect class the repo itself documents at `test_tokenizer.py:44-46`: *"An earlier
metric stripped both, which would have hidden leading- and trailing-whitespace loss."* The strip
simply moved upstream into the corpus exporter.

### M2 — `.github/workflows/ci.yml` is untracked

`release.yml` (modified, uncommitted) declares `uses: ./.github/workflows/ci.yml`. The committed
`release.yml` is the pre-audit version: build and publish on any `v*` tag, no test, no lint, no
version guard.

For a fresh clone or a collaborator's PR there is no CI at all. If `release.yml` is committed without
`ci.yml`, the reference does not resolve and GitHub rejects the workflow — which fails safe, but
silently kills the release path.

### M3 — Version, tag, changelog and PyPI all disagree

```
pyproject.toml   1.0.0          (uncommitted)
CHANGELOG.md     [1.0.0]        (uncommitted)
git tag -l       …v0.2.3        (no v1.0.0)
PyPI             0.2.3, 2026-04-27
```

Harmless today because 1.0.0 is unreleased. It becomes real the moment H2 is executed carelessly.
Separately, tag `v0.2.2` exists with no corresponding PyPI release — prior evidence that the
pre-audit release path failed silently.

### M4 — Workflow actions pinned to mutable major tags on a token-minting job

`release.yml` holds `id-token: write` for trusted publishing while using `actions/checkout@v5` and
`astral-sh/setup-uv@v7`. Those are moving refs. Trusted publishing removes the long-lived-secret
risk but not this one. Pin to full commit SHAs.

### M5 — `model_card.json` says "no cap" while coverage is capped at 5,000 lines

`scripts/train_tokenizer.py:94` computes coverage over `val["mon"][:5000]`, while `:189` writes
`"sampling": "whole split, no cap"` as a hardcoded string. `tests/test_model_card.py:126-128` then
asserts that string — a guard that cannot detect the thing it names.

The module docstring at `:8-12` describes removing exactly this head-of-file bias. It is still live
for the coverage metric. Compression and round-trip figures *are* whole-split; only coverage is
affected.

### M6 — `cli.py` and `trainer.py` have zero coverage, and the contributing doc implies otherwise

`cli.py` is a shipped console entry point with four documented exit codes, none exercised.
`trainer.py` holds the pure functions most worth testing — `filter_partial_syllable_pieces`,
`guaranteed_alphabet`, `corpus_fingerprint`, and the byte-piece injection in `_finalise` that the
entire byte-fallback guarantee rests on. All are testable without a corpus, in milliseconds.

## Low

- `default_model_path()` promises zip-safety its implementation does not deliver:
  `Path(str(resources.files(...)))` collapses the `Traversable` back to a filesystem path.
  `importlib.resources.as_file` is the API with the stated property. Fails loudly, not silently.
- `load_tokenizer` is typed `str | None` while `MonTokenizer.__init__` accepts `str | Path | None`.
  With `py.typed` shipped, a consumer passing a `Path` gets a false type error — the exact defect
  class `tokenizer.py:99-101` criticises in v1.
- The cached `tokenizers.Tokenizer` is shared across instances via `lru_cache`, so
  `enable_truncation` on one `MonTokenizer` reconfigures every other in the process.
- Drift: `trainer.py:96` defaults `vocab_size=48_000` while the shipped artifact is 64,000;
  `CHANGELOG.md:62` says 98 tests where 100 collect.

## What is good, specifically

- **Serialising the normalizer into `tokenizer.json`** (`trainer.py:196`) removes train/inference
  skew by construction rather than by discipline. The strongest single architectural decision in the
  toolchain.
- **`tests/test_packaging.py` tests the built wheel, not the source tree** — dependency leakage,
  version agreement, manifest correctness. It guards defects that verifiably reached PyPI: 0.2.3 on
  PyPI really does declare `twine>=6.1.0` as a runtime dependency.
- **`tests/test_normalization.py:29-45` is exhaustive over all 1,114,112 codepoints**, comparing the
  Python normalizer against the Rust one baked into the artifact. Asserting rather than assuming that
  `\p{Zs}` matches `unicodedata.category == "Zs"` is the right instinct and costs milliseconds.
- **Byte fallback is genuinely proven.** `test_every_byte_piece_is_present` checks all 256 `<0xNN>`
  pieces exist — the thing `byte_fallback=True` silently needs. Round-trip is verified across emoji
  with ZWJ, Thai, CJK, Greek, Cyrillic, Hebrew, IPA and maths.
- **`metrics.py:84-112` returns `None` rather than guessing** when pieces do not reconstruct, and
  callers count it as unreconstructable. Refusing to flatter a metric is rare.
- **The tag-versus-version release guard is correct.** `release.yml:41-53` compares `GITHUB_REF_NAME`
  against `uv version --short` and exits 1 on mismatch, in a job that `needs: ci`, before publish.
- **`docs/architecture.md` records reversal conditions and negative results**, including that *"the
  claim that atomicity matters is inherited, not tested."* That is the right epistemic posture.

## Roadmap

**Immediate.** H2 (`git add -A`, then commit — this also lands M2), then M1: add `" abc"` and
`"a▁b"` to the probes and the whitespace test so the blind spot closes before the claim is either
narrowed or fixed.

**Next.** Decide H1 — retrain with `prepend_scheme="never"`, or narrow the documented claim. Then M5
and M6.

**Long-term.** M4 (SHA-pin the actions). Consider LFS for the 4.8 MB artifact before the next
retrain; at the current cadence this is not urgent.
